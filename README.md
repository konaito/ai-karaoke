# KARAOKE / 曲ライブラリ

曲を選んで歌う・聴く静的PWAです。「愛を伝えるだとか」「時定数の低い世界で」を収録しています。ヘッダーの曲名から切り替えられ、`?song=jiteisu` のようなURLで曲を直接開けます。曲を変えると現在の音声を停止し、選んだ曲を最初から準備します。

## 曲の追加

プレイヤーのソースを書き換えず、[生成パイプライン](pipeline/README.md)で作ったビルドを登録します。

```bash
python3 scripts/register-song.py --id new-song --build /path/to/generated-player
python3 scripts/check-library.py
```

`catalog.json` が曲一覧、`songs/<id>/song.json` が曲情報です。音源・カバー・文字タイミングへの参照も曲情報にまとまっています。登録コマンドは既存IDを上書きしません。生成データの更新時は `sw.js` のキャッシュバージョンとHTMLのアセットバージョンを更新してください。

Service Workerは曲一覧を読み、全収録曲をオフライン用に保存します。今回の2曲は初回ダウンロード後に曲を切り替えても使えます。新しい版は再生を中断せず更新ボタンで適用します。

`pipeline/` と `examples/` に認識・再生成のプログラム、固定依存、元歌詞と認識結果を保存しています。元の56行タイムラインは歴史的な基準ファイルと完全一致するテストを保持。収録版では「AI」の表示2文字へ既存の4文字の時刻を統合し、その行が行単位表示へ落ちる問題を補正しました。

## プレイヤーの実装メモ


このディレクトリは複数曲対応の静的PWAです。`VERSE`や`CHORUS`は歌唱セクション名です。音源・歌詞・ボーカル低減・マイクの音程検出はブラウザ内で動き、サーバーへ音声データを送信しません。

**スマホUIファースト。** Android縦画面を基準に、片手操作・読みやすい二段歌詞・スクロールと見切れのない画面を設計します。曲のアートと音程モニターは同じ領域で切り替え、歌詞と再生操作を常に確保します。設定は三つのタブで切り替えます。横画面とPCはスマホ版から拡張します。

調査根拠、旧UIの問題、設計方針、検証範囲は [UI-DESIGN.md](./UI-DESIGN.md) を参照してください。

## 再生モード

画面上部の切替で、同じ歌詞表示を保ったまま「カラオケ」と「プレイヤー」を切り替えられます。

- **カラオケ**: WASMのボーカル低減、キー変更、マイク音程モニターを使えます。
- **プレイヤー**: OS標準の`HTMLAudioElement`で原音を再生します。リピート再生、ロック画面／通知領域の再生・一時停止・前後シークに対応し、歌詞は再生位置に合わせて表示します。

プレイヤーモードは、ブラウザのメディア再生機構とMedia Session APIを使うため、対応ブラウザ・OSでは画面を閉じたり別アプリへ移動したりしても再生を継続できます。最初の再生開始は必ずユーザー操作から行ってください。カラオケモードのWASM処理は、バックグラウンド再生を優先するプレイヤーモードでは使いません。

## ローカルで確認

```bash
cd karaoke
python3 -m http.server 4173
```

`http://localhost:4173/` を開きます。`file://` 直開きでは、Service WorkerとWASMのために正しく動作しません。

## PWAの更新

GitHub Pagesに新しい`sw.js`が配信されると、Service Workerが新しいキャッシュを準備します。アプリは起動時・タブ復帰時・フォーカス時・15分ごとに更新を確認し、再生していないときは自動で新しいWorkerへ切り替えてページを再読み込みします。歌唱中・再生中は勝手に中断せず、「更新があります」ボタンから適用できます。

更新処理では`updateViaCache: "none"`でWorker本体のHTTPキャッシュを避け、インストール時の各アセットも再取得します。`CACHE_NAME`と`app.js`／`styles.css`のクエリバージョンを更新し、古いキャッシュを`activate`時に削除します。

## WASMを再ビルド

```bash
./karaoke/scripts/build-wasm.sh
```

`wasm/src/lib.rs` のDSPは、中央定位の高域成分を抑え、低域の中央成分を残すボーカル低減と、マイクのRMS/自己相関ピッチ検出を担当します。歌唱位置は`alignment.json`のローカル解析済み文字タイムラインで追い、現在行の各文字を実測時刻に合わせて塗ります。

## GitHub Pages

`.github/workflows/karaoke-pages.yml` は `main` の `karaoke/` 配下が更新されたとき、ディレクトリをそのままPagesへデプロイします。GitHubリポジトリの Settings → Pages → Source を `GitHub Actions` に設定してください。

## 日本のカラオケ採点との関係

DAMの精密採点Ai/DX-GとJOYSOUNDの分析採点AIを調査し、歌唱画面と採点結果画面を分ける設計にしています。公式説明では、歌唱中はガイドメロディーに対する歌唱軌跡、音程の一致、こぶし・しゃくり・フォール・ビブラートなどをリアルタイムに表示し、歌唱後に音程・安定感・表現力／抑揚・ロングトーン・テクニックなどをまとめて確認します。DAMはAi感性メーター／ボーナス、JOYSOUNDはAIゲージ／AIボーナスという独自要素を持つため、同じ「採点」と呼んでも内部計算は各社固有です。

このアプリの現在のマイク画面は、音程と声量の**練習モニター**です。DAM／JOYSOUNDと同等の採点を実装したとは表示しません。正解メロディーの音符列、フレーム単位の歌唱ピッチ、無声音・子音・発声開始の扱い、区間集計、歌唱技法検出、結果画面の集計が揃って初めて、ローカル練習採点として実装できます。

参考にした公式情報:

- [精密採点Ai（カラオケDAM公式）](https://www.clubdam.com/contents/saiten/seimitsusaiten_ai.html)
- [精密採点DX-G（カラオケDAM公式）](https://www.clubdam.com/contents/saiten/seimitsusaiten_dx_g.html)
- [分析採点AI＋/AI（JOYSOUND公式）](https://www.joysound.com/web/s/joy/bunseki)
- [分析採点AI＋/AIの遊び方（JOYSOUND公式）](https://www.joysound.com/web/s/function/bunseki)

## 既知の制約

歌詞タイミングは既知の歌詞を正として、ローカルの日本語`faster-whisper-small`が返した発声区間を文字単位へ展開したものです。従来のBPMグリッドより厳密ですが、歌唱専用の音素強制アライメントや正解メロディーとの比較ではありません。低信頼度の文字も`alignment.json`に残しています。マイク画面は音程モニターであり、採点画面ではありません。

このWAVは完成済みのステレオミックスで、分離済みボーカル/伴奏ステムではありません。そのため、アプリの「ボーカル低減」は機械学習による完全なステム分離ではなく、中央定位成分をWASMで抑える方式です。声の残響や中央のスネア/ベースが少し残る場合があります。
